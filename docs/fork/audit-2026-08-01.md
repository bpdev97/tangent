# Tangent fork audit: 2026-08-01

## Result

The fork was reduced to seven intentional features after merging upstream `283c7ac4` into the
previous Tangent tip `cef261314` (merge `dbba8fff8`). The reviewed working tree differs from that
upstream baseline in 298 paths; most of the volume is Hermes, the APNs relay, distribution
workflows/assets, and personal identity. [`FORK.md`](../../FORK.md) is the authoritative active
registry.

The reduction follows these decisions:

- keep Tangent distribution, releases, server updates, and separate state;
- keep generic chats;
- keep Hermes and its automation UI;
- keep personal notifications and Live Activities;
- keep shared HEIC/HEIF normalization;
- keep Codex MCP tool-call approvals because upstream still lacks the end-to-end request handler;
- keep Control-N/Control-P palette navigation;
- restore upstream for general mobile reliability/rendering, general activity/tool projection,
  provider-neutral agents, Claude lifecycle patches, Cursor ACP patches, completed-turn retention,
  and iOS composer behavior.

## Defects found and disposition

### Accepted limitation: generic chat is not filesystem containment

The managed scratch directory is the provider cwd, and the server adds a no-filesystem instruction
to every provider turn. This is not an operating-system jail. Codex's forced `approval-required`
mode limits writes but does not create a provider-independent read boundary, and other providers do
not expose one shared enforcement mechanism.

The UI and deep-link guards prevent accidental project-tool entry, and the docs now state the
boundary honestly. Strong containment would require provider-specific denial or a separately
sandboxed runtime. That is intentionally outside this reduction rather than being “fixed” with more
prompt text.

### Fixed by restoration: quadratic reasoning writes

The fork-specific reasoning accumulator persisted the complete growing text for every delta through
an unbounded serial worker. Restoring upstream `ProviderRuntimeIngestion` removed that projection.
Hermes now emits canonical `reasoning_text` deltas and uses upstream ingestion/presentation.

### Fixed: push retention and avoidable per-device work

The relay previously retained abandoned activity rows indefinitely, scanned and decoded all of them,
recomputed the same aggregate for every device, opened a new APNs HTTP/2 connection per send, and
allowed the ordered publication promise chain to grow without a bound.

Activity rows now carry phase-specific expiration timestamps and are physically pruned. Each
publication computes one aggregate, fans out with bounded concurrency, and is rejected with 429 if
the ordered queue is full. APNs sessions are reused by environment and closed on shutdown. Delivery
watermarks remain channel-specific so transient failures are retryable without duplicating a
successful channel.

### Fixed: updater memory and disk growth

The server updater previously buffered as much as 200 MiB with `Response.arrayBuffer()` and kept
every archive. It now streams to a unique temporary file while enforcing the byte limit and hashing,
verifies SHA-256 before rename, removes failed temporary files, and retains the current plus one
previous archive. Tests explicitly fail if the archive path tries to call `arrayBuffer()`.

### Fixed: routine mobile update failures surfaced as defects

The automatic Expo update check converted ordinary rejected promises, including offline and
development-client failures, into defects and logged them as fatal atom-command errors. In a
development build that produced a visible error overlay even though the updater had already
recovered. Launch checks now fail quietly, while manual checks continue to surface the concrete
error through their settings UI callback.

### Fixed: oversized image stub exhausted the CI test budget

The upstream image-compression failure-path test allocated repeated multi-megabyte blobs. It passed
alone but timed out at 15 seconds during the exhaustive parallel GitHub run. The test now drives the
same over-budget branch with a 256-byte encoded stub and a 100-character budget. Production image
compression remains unchanged.

### Fixed by restoration: eager custom MCP activity projection

The fork's custom 32 KiB MCP projection serialized the complete candidate before bounding it.
Restoring upstream `ActivityPayloadProjection` removed the fork-owned implementation and its claim
of a bounded transient cost.

### Fixed: incomplete HEIC identification

Upload normalization previously required `image/*` at orchestration ingestion and inspected only
the ISO-BMFF major brand. It now accepts a non-image MIME only when a bounded `ftyp` parse finds a
known HEIC major or compatible brand. AVIF is not treated as HEIC merely because it is ISO-BMFF.
The real-image integration test covers an `application/octet-stream` HEIC upload.

### Fixed: Hermes lifecycle correlation and lock retention

Hermes previously allocated a random ID for each malformed subagent event and retained one semaphore
for every thread for the adapter lifetime. Subagent notifications without `subagent_id` are now
ignored instead of creating unrelated rows; valid IDs map to upstream `task.*` lifecycle events.
Lock entries are reference-counted and removed after the final user exits the critical section.

### Corrected: MCP approval naming

The Codex extension labeled every tagged MCP approval as “computer use,” even though the protocol
can name any MCP server/tool. Server, web, mobile, and documentation now call it an MCP tool-call
approval. Session persistence is shown only when Codex advertises it.

## Decisions reviewed without a defect finding

- Generic project provisioning is idempotent and repairs only the reserved title/path, preserving
  model preferences and existing threads.
- Generic sessions compare against the forced effective runtime mode and ignore stale worktree cwd.
- Hermes `prompt.submit` is supervised outside `sendTurn`, so steering, interruption, approvals, and
  open-ended input remain reachable while a turn runs.
- The personal push bridge keeps the last usable bearer endpoint while prepared WebSocket state is
  replaced, avoiding notification re-registration churn without retaining the removed general
  mobile wakeup patch.
- Codex still requires a Tangent extension for tagged empty-form
  `mcpServer/elicitation/request`; rich forms and unknown elicitations are canceled rather than
  guessed into an approval UI.
- Control-N/P delegates to the existing command-palette next/previous actions and is scoped to the
  open palette.

## Verification boundary

The reduction included history and tree comparison, focused source review of every retained feature,
deterministic server/web/mobile unit tests, repository checks, and integrated web/iOS client passes.
Real APNs delivery, notarization, TestFlight processing, and GitHub-hosted release jobs remain
external release-workflow responsibilities; their workflow runs and resulting artifacts are linked
from the release handoff rather than represented as local tests.
