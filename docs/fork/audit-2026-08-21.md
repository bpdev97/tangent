# Tangent upstream sync audit: 2026-08-21

## Result

This sync merges `upstream/main` at `592c5983c` into Tangent tip `a455138e8`. The range contains 95
upstream commits after the previous `bab4b6f02` baseline. The upstream server package remains at
`0.0.33`, and the range contains no database migration or mobile native configuration change.

The merge follows upstream implementations and UI structure wherever possible. No active feature
registered in [`FORK.md`](../../FORK.md) has an upstream equivalent yet, so none can be removed in
full. Shared implementations that did overlap were reduced to narrow Tangent hooks described below.

## Upstream changes adopted

- macOS launchd background-service support and the shared platform-manager abstraction;
- workspace headers, environment-scoped provider presentation, composer task/stash drawers, and
  compact approval actions;
- stricter remote-editor deep-link validation;
- desktop window destruction before backend shutdown and activation suppression while quitting;
- browser defaults, audio controls, hidden-preview throttling, and removal of timer-driven loading
  progress rendering;
- provider-session reconciliation, fresh thread bootstrap retries, task-liveness fixes, provider
  skill discovery, and tool lifecycle identity;
- pull-request refresh, review verdict, and API-budget improvements; and
- the upstream provider defaults, including Cursor enabled by default.

## Fork reduction

- Background-service orchestration now uses upstream's systemd/launchd manager model. Tangent owns
  only distribution identity, its verified GitHub Release runtime source, and the associated tests.
- The sidebar uses upstream's reusable `SidebarUtilityMenu`; Tangent contributes one Automations
  item instead of carrying a second footer implementation.
- Desktop lifecycle tests use upstream's shared fixtures and quit-order assertions, with only the
  Quick Chat URL assertion added.
- External URL handling uses upstream's constrained remote-editor validator. Tangent adds only the
  exact `linear.app` and `linear.review` deep-link hosts.
- Linear preview presentation adopts upstream's browser and loading behavior while retaining the
  dedicated chrome suppression required by `FORK-LINEAR-001`.
- Generic chats use upstream's workspace, provider, task, and composer structures. The remaining
  delta is the documented chat-runtime lock and removal of project-only controls.
- Codex approvals use upstream's compact components and labels. Tangent retains only tagged MCP
  request semantics and conditional session persistence.

## Explicit downstream decisions retained

- `FORK-DIST-001`: Tangent must coexist with official T3 Code. Linux uses `tangent.service`; macOS
  uses `com.bpdev97.tangent.service`, not upstream's `com.t3tools.t3code.service`. Runtime archives
  continue to come from verified Tangent GitHub Releases rather than npm.
- `FORK-CHAT-001`: managed generic chats and Quick Chat remain because upstream has no projectless
  chat environment or equivalent host-selection policy.
- `FORK-HERMES-001`: Hermes and automation management remain additive. Upstream's unknown-driver
  compatibility and task lifecycle are used without a parallel Tangent abstraction.
- `FORK-CODEX-001`: MCP elicitation remains because upstream does not yet decode the tagged Codex
  request or advertise per-request persistence support.
- `FORK-LINEAR-001`, `FORK-MERMAID-001`, `FORK-PREVIEW-001`, `FORK-PUSH-001`,
  `FORK-IMAGE-001`, and `FORK-PALETTE-001` remain for the reasons and removal conditions recorded in
  the registry. None has an equivalent upstream implementation in this baseline.

## Compatibility corrections

- Background-service onboarding now correctly says launch agents run only while the macOS user is
  logged in.
- Tangent's launchd label and plist filename are derived from the distribution identity, preventing
  collisions with an installed official T3 Code service.
- Install documentation now matches the effective provider defaults: Codex, Claude, Cursor, and
  Hermes are enabled; Grok Build and OpenCode require opt-in.
- Background-service documentation now covers both Linux and macOS with Tangent-specific unit
  paths and release installation instructions.
