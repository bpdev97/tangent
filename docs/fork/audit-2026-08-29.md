# Tangent upstream sync audit: 2026-08-29

## Result

This sync merges `upstream/main` at `c0e09f323` into Tangent `main`. The range contains 59 upstream
commits after the previous `a6797b3b9` baseline and advances the server package from 0.0.35 to
0.0.36. The selected upstream commit is also tagged as a 0.0.37 nightly.

The merge follows upstream wherever Tangent has no documented exception. It adopts Expo SDK 57,
Uniwind mobile themes, generalized file attachments, environment-published themes, searchable
project filtering, project-default model selection, provider reliability work, WSL runtime caching,
and desktop preview efficiency improvements. Every registered fork feature remains active.

## Upstream changes adopted

- mobile advances to Expo SDK 57 and React Native 0.86, compiles semantic themes through Uniwind,
  hardens native header transitions, restores composer glass, and improves Android file actions and
  adaptive icons;
- turns can attach PDFs, ZIPs, and other files, with server uploads up to 50 MB and persisted draft
  attachment state;
- environments can publish theme files, clients synchronize those themes, and web settings expose
  the resulting palettes;
- the sidebar project filter is now searchable, keybindings use standard settings rows, and project
  default models are honored when a new thread is created;
- OpenCode gains child-approval, stop, catalog, ownership, and text-generation reliability work;
  Codex gains bounded input buffering, account-plan compatibility, and sub-agent model display;
- failed first sends and automatic title generation can retry, while the final upstream state keeps
  automatic thread settling enabled by default;
- desktop browser previews suppress duplicate updates, stop hidden surfaces from draining battery,
  support OAuth popups and picture-in-picture wiring, and verify preload bundles; and
- WSL environments cache the runtime on the Linux filesystem to reduce launch overhead.

## Fork compatibility decisions

- `FORK-DIST-001` keeps Tangent names, bundle IDs, URL schemes, state roots, personal release tags,
  and `tangent-server` artifacts. Upstream CI and release improvements are adopted without replacing
  the personal macOS and iOS workflows.
- `FORK-CHAT-001` keeps generic chat as a managed environment with its own runtime and cwd rules.
  Generic chat remains a separate sidebar row and command-palette action; project scopes adopt the
  searchable upstream combobox, and both project and generic drafts use upstream's shared default
  model resolver.
- `FORK-HERMES-001` keeps its supervised TUI-gateway transport, profiles, automation projection,
  and migration baseline. The OpenCode and Codex adapter changes remain provider-local.
- `FORK-PUSH-001` retains Tangent mobile registration and relay behavior through the SDK 57 app
  bootstrap. No upstream mobile identity or scheme replaces the fork's push identity.
- `FORK-IMAGE-001` keeps shared image normalization and adopts upstream's generalized attachment
  persistence and upload contracts around it.
- `FORK-PALETTE-001` remains the shared command surface. The upstream palette retains distinct New
  chat and project-thread actions.
- `FORK-LINEAR-001` remains wired through server startup and desktop/web preview destinations.
- `FORK-MERMAID-001` is unchanged while nested Markdown image rendering and file previews adopt
  upstream fixes.
- `FORK-PREVIEW-001` keeps per-thread mount ownership and settled-thread teardown. Upstream's hidden
  surface suspension, duplicate-update suppression, OAuth handling, and picture-in-picture prop are
  layered onto that lifecycle instead of replacing it.

The SDK 57 migration removed mobile `useThemeColor` escape hatches and the old `ComposerSurface`
dark-mode prop. Tangent-owned chat and automation screens now use the same semantic Uniwind classes
as upstream. This is a compatibility adaptation, not a fork-specific styling divergence.

- dependency installation from the merged lockfile;
- `vp check` with zero errors, `vp run typecheck`, and `vp run lint:mobile`;
- focused suites covering all registered fork features plus the conflicted web, server, contracts,
  desktop, and mobile paths;
- the six-workspace production build and standalone server bundle;
- an isolated paired web pass covering the searchable project scope, a project-backed new-thread
  draft, the generic-chat entry point, and both actions in the command palette; and
- a clean Expo SDK 57 iOS prebuild, CocoaPods install, Xcode simulator build/install/launch, merged
  Metro bundle, disposable-environment pairing, Tangent home composer rendering, and runtime-log
  scan with no crash or unhandled-error matches.

`vp check` reports 12 non-fatal warnings: eight are in files changed by this upstream range and four
are pre-existing sites outside the range. Mobile native static checking passed; optional SwiftLint,
ktlint, and detekt executables were not installed. Xcode emitted dependency warnings during the
clean build but completed successfully.

XcodeBuildMCP inherited the machine's Xcode beta selection and could not load SimulatorKit for
semantic UI capture. Its build, launch, runtime logging, and screenshot tools remained available.
The pinned serve-sim wrapper launched for the same simulator, but the collaborative browser could
not snapshot its frame, so the mobile visual proof uses the direct simulator screenshot.
